1.0

Start with the execution problem

One fixed horizon cannot fit every moment.

Long chunks preserve motion but postpone feedback. Short chunks observe often but interrupt stable behavior. The useful horizon changes with the state of the task.

The novelty

The action horizon becomes an inference-time decision.

GeoAAC does not ask the policy to predict another control signal. It measures how candidate action prefixes evolve during Flow Matching denoising, then uses that geometry to decide how much of the chunk to execute.

2.0

Read the latent signal

Flow trajectories expose action reliability.

When a prefix settles into a consistent path, its geometry stabilizes. Persistent variation indicates that future actions remain uncertain and the robot should observe sooner.

4.0

Complete the inference loop

Five operations. No policy retraining.

  1. 01Flow-based VLA

    Predict a candidate action chunk from the current visual-language context.

  2. 02Denoising trajectory

    Retain intermediate action states along the Flow Matching path.

  3. 03Prefix geometry

    Measure how each candidate prefix changes through denoising.

  4. 04Temporal correction

    Stabilize the signal across consecutive robot observations.

  5. 05Adaptive horizon

    Execute the longest prefix whose geometry indicates reliability.
